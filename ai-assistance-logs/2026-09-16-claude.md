## 1. User request

**QDVC Research Pipeline** is a single-file web application which helps a university academic (researcher, scholar, lecturer, professor) keep track of their research paper pipeline, from ideation to submission, then submission, revision, and eventual publication.

Each **paper** has:
- A unique ID in format `00AA` (2 digits, 2 capital letters), e.g., 26AB, 25CD, 24EF. The first 2 digits indicates the year that the paper was first conceived, then 2 letters are arbitrary but somewhat meaningful (e.g., 22VF might be a paper from 2022 on Videoconferencing Fatigue).
- A title (text string).
- Coauthors.
- Work status
    - On hold
    - With me
    - With a coauthor
    - Under review
    - Published
- Publication route (conference OR journal OR other)
- Publication events, which can be optionally tagged as one of these predefined types:
    - If conference paper:
        - Submitted to conference
        - Received decision from conference (reject OR revise OR accept)
        - Resubmitted to conference
        - Included in conference proceedings
        - Presented at conference
    - If journal paper:
        - Submitted to journal
        - Received decision from journal (reject OR revise OR accept)
        - Resubmitted to journal
        - Published online
        - Publised in print (volume and issue)
- If journal paper: optional link to the conference paper that it was developed from

The user interface should have the following:

- Simple data table with all projects, making it possible to create, read, update, delete (CRUD operations)
- A kanban board view, based on work status
- A timeline view, generated based on the publication events, so the user can visually see how long a paper has been at a particular step

User data is to be stored in browser LocalStorage. It must be possible to import/export all user data (JSON).
